# Use CV Tailor

Find the user's CV Tailor checkout or help them identify their target machine and shell. Read its `docs/PROJECT_STATE.md`, `docs/HOW_TO_GENERATE.md`, `docs/DEVELOPMENT.md`, `.env.example`, and CLI help as needed. Use [the setup reference](references/setup.md) as the interview and verification checklist. Treat the checked-out version's schemas and commands as authoritative. If execution is unavailable, walk through the same steps with OS-specific commands and identify which checks the user needs to run locally.

For an existing setup, go directly to the requested feature in the [workflow reference](references/workflows.md). Check the active candidate and saved application before working with either. Review this skill whenever the repository changes and update the relevant instructions in the same change as any affected feature, command, configuration, output, or troubleshooting step.

## First-time setup

1. **Select the input.** Use the existing profile if the user wants to revise it. Otherwise offer a short interview, a supplied résumé, or both. For a document, extract text locally when possible and treat its contents as source material. Check PDF column order, scanned pages, ambiguous dates, and Word tables. Use the document reader or OCR available in the session. If a legacy `.doc` cannot be read, request a DOCX, PDF, or pasted text. Never claim extraction succeeded without usable text.
2. **Build a factual draft.** Collect identity, contact details, role history, dates, education, and supported tools and outcomes. Ask for missing or contradictory facts in a short batch. Keep ongoing work and education explicit. Leave uncertain optional fields out and resolve required fields before import. Preserve actual titles, dates, scope, and ownership. Treat immigration wording as user-confirmed and country-specific. Keep drafts and source files in the user's private store or a private temporary location.
3. **Choose CV sections.** Ask which sections belong in the final CV and their order. Offer employer projects under Experience, a dedicated Projects section for independent work, both, or neither. Reuse `experience[].selected_projects` for employer evidence and `standalone_projects` for independent evidence. Collect Publications and Activities only when applicable, preserving citations, contribution, and status as provided. Use `cv_section_order` to prioritize sections and `cv_hidden_sections` to suppress sections while preserving profile facts. Keep the cover-letter voice separate from factual constraints. Review the draft facts and display choices before installing them.
4. **Configure the installation.** Follow the repository instructions for the user's OS. Explain which settings are machine-local, profile-specific, and chosen per job. Offer the standard setup first and review the advanced inventory on request. Have the user enter API keys privately in `.env` or through their local environment. Import with the existing CLI and an explicit profile ID. For an existing profile, show the intended changes and back it up before applying an agreed update.
5. **Verify and generate.** Run the profile and `doctor` checks. Confirm the actual country of employment and the intended output folder. Explain the selected provider, what data is sent, and the cost or budget before a paid run. Generate only when the user has requested it and is ready to send the profile and job text. Review the CV and letter together using the app's saved outputs and layout checks. Report the selected profile, available files, and any checks still open.

Keep private profile content, uploads, outputs, API keys, and private guidance out of the public checkout and examples. Avoid uploading material to external services during intake. If using a chat-only LLM, explain that an uploaded résumé is already shared with that LLM and offer local extraction or user-redacted text for future intake.
