# CV Tailor workflows

Resolve paths from the checkout and use its venv Python. Check `docs/PROJECT_STATE.md` for the available features and known blockers, and `docs/HOW_TO_GENERATE.md` for current examples. Keep real profiles, postings, credentials, and outputs in the private store. Use an explicit profile ID for CLI and API operations. In the GUI, confirm the name and ID shown in the header before making changes.

| Task | Workflow |
| --- | --- |
| Set up or diagnose | Use the setup reference for profile intake and settings. Run `cvtailor.py --profile-id <id> doctor` or **Settings & help → Run local setup checks**. Use `doctor --verify-key` only when a network check is wanted. See `docs/MAC_SETUP.md` for a new Mac and `docs/DEVELOPMENT.md` for environment and ports. |
| Manage profiles | Use `profile list`, `new`, `show`, `import`, or `export`; check their help for options. Resolve CV sections and project placement in the private profile. Add confirmed publications and activities as single-line entries, or `{text, bullets}` when detail bullets are wanted (they print as nested sub-bullets). Use the GUI sidebar to switch candidates and confirm the active identity. |
| Find jobs | Use **Find jobs** or `jobs search`; use `jobs sources` to see source coverage. Explain matching and eligibility notes. **Use this posting** transfers available text without generation. Check the full posting and the actual work country. |
| Generate a CV and cover letter | Use **New application** or `generate --job-file <file>` with the actual company, role, and work country if known. Read `.agents/skills/cv-tailor-application/SKILL.md` for tailoring and review details. Confirm the configured provider and budget. Explain normal cache reuse before forcing a fresh paid draft. |
| Review a saved application | Open **Applications** and select the correct candidate's record. Use **Documents** for PDF checks and downloads, **Details** for the source posting, profile comparison, explanation, and run history, and **Application folder** for editable inputs and local output paths. Check that each role or project bullet tells one main achievement and usually fits one or two lines. Keep a project heading when several short bullets make the evidence easier to scan. If the CV overflows, the automatic retry targets about 10% fewer words in the visible, editable prose and keeps standalone project text selected verbatim. Inspect partial outputs before retrying failures. |
| Revise or re-render | Edit the saved application content for job-specific revisions and use `render --content <path>` or the documented application render script. Use a private copy when comparing revisions. A local render uses existing content; fresh generation calls the provider. Preserve manual edits and verify the final layout. |
| Compare pagination and export | Choose **Balanced page breaks** for a new application or use **Documents → Compare CV page breaks** on an existing one. Save the preferred preview separately. Use **Create / refresh CV for autofill** for Word and text from the saved snapshot (headings, short month dates and nested publication bullets match the PDF). A valid older snapshot can be used in place; use the freshness indicators to verify the refreshed files. Use the available PDF extraction and Word layout checks before delivery. |
| Review suggested claims | `generate` prints a hint (`N suggested claims to review: ... claims list --content ...`) when a run stored suggestions. Run `claims list --content <app>/source/content.json` (or open **Suggested claims** on the saved application). Ask the user which statements are TRUE of them; never accept on their behalf, and never accept an untrue or doubtful one. `claims accept <numbers>` (or **Add selected to my profile**) adds only those to the private profile after a timestamped backup, then regenerate with `--no-cache` so they can appear. `claims reject <numbers>` (or **Dismiss selected**) records the rest and leaves the profile unchanged. See the Confirm-first suggestions section of `docs/HOW_TO_GENERATE.md`. |
| Check saved applications against current rules | `cvtailor.py --profile-id <id> applications check [--render]` (or `scripts/check_saved_applications.py --profile-id <id>`). Free and offline: no model call, and it never writes to the store. Exit code 1 if any application FAILs, which means today's validators would make the generator retry that draft; decide with the user whether to edit `source/content.json` and re-render or regenerate. Run it after pulling a new version. It does not cover work-authorization wording. See `docs/HOW_TO_GENERATE.md`. |
| Answer portal questions | Open **Answers** on a saved application or choose **Answers only**. Add questions, limits, and confirmed facts or public excerpts. Draft selected answers when the user wants a paid model call. Apply the desired draft, edit it, and save a revision. Verify against the cited evidence before use. |
| Automate with the local API | Check `GET /health` and inspect the checked-out API schema in `backend/main.py` and `backend/models/requests.py`. `POST /api/tailor` takes `profile_id`, `job_description`, and optional company, role, country, and cache fields. Use the candidate-scoped download endpoints and the returned job ID. |
| Move or sync the store | Follow `docs/PRIVATE_STORE_SYNC.md`. Check the currently approved pilot scope, back up each store, and confirm both peers are current before editing shared application sources. Keep credentials and machine-local configuration outside synced folders. |

When a task needs a feature that the checkout lacks, report the gap and use the closest supported path the user approves. Check a real result after acting. For a local configuration change confirm it loads, for a saved answer confirm the revision, and for a document check the generated file and its layout. The shared PDF template gives wide candidate names their own row to keep name text separate from contact details during extraction.

In a saved application's **Documents** tab, open **More downloads and document checks** and click **Check PDFs** to flag CV bullets spanning three or more rendered lines. Use the page, line count and opening words to find and review them.

The PDF, DOCX and text CV show one Technologies list per role, combining tools from the role and the employer projects displayed for it. Independent projects show their own technologies.
